# GO2 终点控制

`algorithm/plan_manage/src/go2_cmd_adapter.cpp` 接收 SCAN B 样条，将运动转换为
`/cmd_vel`。终点区的距离减速只影响平移，不再缩小角速度。

- 运动中进入内部停车圈并满足可选 Z 条件后，逐步将速度指令降至零。实测运动持续稳定且停车位置仍符合到达容差时，按目标时间戳回执一次。
- 终点减速区内，朝向误差超过 `terminal_rotate_enter=0.50` rad：先平滑减小平移，
  原地调整朝向；误差降到 `terminal_rotate_exit=0.30` rad 后恢复平移。
- 远离终点时保留 `heading_error_threshold` / `rotate_exit_ratio` 的既有门槛。
- 在终点区继续跟踪有效样条，平移速度上限随到停车圈的剩余距离递减。
- 常量轨迹或已经到达的局部轨迹尾端不授权直接冲向最终目标，保持等待新轨迹，
  超时返回失败。只有最终目标的准入条件可触发到达回执。

无进展分别判定：转向看角度误差降低（同时要求实际朝向变化，轨迹更新本身不算进展）；
终点区平移看目标距离缩短；远段平移看实际位移，允许绕障时暂时远离最终目标。
切换转向/平移阶段会重新开始本阶段计时，普通 B 样条重规划不会重置计时。
`terminal_failure_seconds=8.0` s 控制无进展时限。失败原因分别是 `execution_heading_no_progress`、
`execution_no_progress`。

`execution_timeout=600.0` s 是单个最终目标的总执行预算，从第一条轨迹开始计算，
不会因阶段切换、重规划或正常进展而延长。超时报 `execution_timeout`。
新目标重置上述状态；同一目标失败后，仅有新轨迹不能重新启动运动。
这些导航判定不改变独立脱困转向/倒退动作的既有执行预算。

上述参数属于 `scan_go2_cmd_adapter` 节点。exploration、步态模式协调器和 RL 策略
不负责这段速度控制，也不因本修改增加路线撤销逻辑。

验证：构建后运行
`ctest --test-dir build/scan_planner -R scan_go2_terminal_control --output-on-failure`。
测试在独立 ROS 域运行真实适配器，使用合成里程计、轨迹和 ROS 时钟，覆盖终点
滞回、终点减速、步态低速停滞、停车回执、速度上限、阶段进展、轨迹守卫和总超时。
它不替代 Gazebo 或真机的行走效果验证。

## 新目标已在到达范围内

SCAN FSM 接收点目标后，先按该目标的 XY 容差及既有楼层条件检查是否到达。
已到达时发布停车轨迹、清除规划重试状态，进入 WAIT_TARGET；不生成零距离全局轨迹。
GEN_NEW_TRAJ 同样在调用局部规划前检查，覆盖目标接收后才进入到达范围的情况。
接收、生成、重规划及执行阶段共用 stopIfPointGoalReached，手动目标到达后不再发布该目标失败。
实际到达回执和 mission_complete 仍沿用执行适配器及航点协调器的现有接口。

这修复了局部规划对小于0.20米距离返回false，累计重试后覆盖已到达回执的问题。
判定始终使用该目标指定容差或默认容差；例如0.16米仍不能算作已到达0.15米目标。

回归：`ctest --test-dir build/scan_planner -R scan_near_goal_arrival --output-on-failure`。
在独立ROS域运行真实SCAN、执行适配器和航点协调器，故意等待0.30秒后才完成任务，
覆盖0.095/0.158米、零距离、默认与指定容差、初次重规划中才到达、楼层拒绝、
失败后新目标恢复，确认不存在 arrived 之后又出现 local_replan_exhausted。

## 未到达的短距离目标

局部起终点三维距离小于 0.20 米不再直接返回失败，而是使用独立的多项式初始化，
不继承旧轨迹尾端。初始化考虑距离、当前速度的制动时间及配置的速度/加速度/jerk，
并保证至少七个采样点；采样次数、最小时间间隔和点数有上限。
后续仍执行同一套 B 样条优化、碰撞检查和速度/加速度可行性检查。
无效或退化输入仍失败，不发送绕过规划的速度命令。

到达条件没有放宽：0.15 米容差下的 0.16/0.179 米目标应生成轨迹，只有位姿进入
容差且楼层相符后才能报告成功。`scan_near_goal_arrival` 同时覆盖这些短目标的规划、
未到达时不误报成功，以及进入范围后的完成闭环。
