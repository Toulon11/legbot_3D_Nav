# 在线分块 PCT 验证记录（2026-11-05）

## 验证对象

固定原点的稀疏分块图、静态成熟冻结、动态新观测触发提交、局部代价更新、
原生 PCT A* 的借用读取接口，以及选点/路径处理/SCAN 回执接口。
动态模式没有地图 TTL，没有计时器主动撤销格子。

## 构建和自动验证

构建并安装 `pct_planner` 和 `legbot_exploration`。
运行探索包的 14 项 CTest 门槛，涵盖：

- 前沿、二维路径安全、路径处理与规划反馈。
- C++/Python 嵌入及原生 A* 分块读取。
- 16 个分块地图用例：Welford、冻结、动态无新点保持原图、阈值和局部更新等。
- 在线 PCT 规划与前沿提取。
- 隔离 ROS 的选点、脱困、地图显示和执行事件。
- 有 CUDA 设备时，同一固定栅格上与原项目 GPU 提取的 G/C 对照。

G/C 对照覆盖三批扩展输入，所有真实 G 和局部保留切片上的 C 均须一致。
稀疏表示省略远处只含 C、没有 G 的低切片；这些格子不产生可行走表面。
该测试不声称新代价和原版未知占位值参与梯度后的代价相等。

## 合成数据的更新开销

输入为 81×81 个真实地面点，每帧 6,561 点；固定 0.10 米栅格，未启用小洞补建。
数字来自本机本次运行，仅用于验证更新机制，不等同于 Gazebo 场景性能。

| 项目 | 本次结果 |
| --- | --- |
| 静态稳定需要的输入帧 | 3 |
| 前三次构图耗时 | 323.49 / 163.03 / 397.42 ms |
| 冻结后相同帧数 | 20 |
| 重复帧融合耗时中位数 | 16.28 ms |
| 重复帧派生地图处理耗时中位数 | 0.0012 ms |
| 重复帧基础/地形/膨胀重算数 | 均为 0 |
| 忽略的静态重复点数 | 131,220 |
| 格子结构数组占用 | 4,685,824 字节，32 块；不含证据和其他工作区 |
| 原有块地址 | 全部保持不变 |

动态模式在同一地面图中加入一个局部障碍点：13,563 个已表示格中，
本次检查 442 个基础格、525 个几何特征格、442 个地形格及 610 个膨胀格，
融合与局部处理共 37.80 ms。局部切片补齐也计入上述数量。

## 联调边界

隔离 ROS 测试模拟 SCAN 成功/失败回执，不验证机器人真实运动。
脱困测试要求匹配的成功回执、重新观测后的普通起点检查通过，以及控制模式恢复正常。

保留全部切片后，封闭下层上方的开放屋顶仍有前沿。
相应用例验证不会隐藏屋顶并误报整图探索完成，不代表已经实现按可达楼层独立完成判定。

没有运行 Gazebo 或真机验收。默认阈值仍是试验值，特别是 G/C 各 0.02 米的提交阈值
需要结合注册点云的测量和位姿噪声标定。按要求去掉 G/C 归并后，跨切片噪声仍可能形成小净空。
