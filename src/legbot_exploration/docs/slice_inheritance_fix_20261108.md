# 局部切片继承缺失与灰斑修复（2026-11-08）

## 问题

旧 `expand_layers` 只把本批新出现的切片向已存在列扩展。若周围先观测为+1厘米，
中心后来才观测为-1厘米，中心可能仅保留低切片，而缺少周围正在使用的+0.5米切片。
真实地面已经三点成熟，规划仍在该层把它当作未知，触发0.40米机体范围的未知膨胀。

## 修改

- 用稀疏分块布尔掩码保存原生切片来源，以及已有局部切片需求。
- 需求覆盖尚未观测的位置；只有该位置后来有真实点云时才创建对应层格。
- 新列从自己的本地需求块继承切片，以本列真实表面重新确定 G/C。
- 区分原生切片与继承切片；继承不会再产生扩展源，避免范围沿地图无限传递。
- 某个继承切片以后确实被本列真实高度范围覆盖时，仍能成为合法的原生来源。
- G/C更新继续触发局部代价、膨胀、连通性、前沿及几何版本更新。

未调整机体半径、安全余量、成熟点数、表面容差或规划阈值。没有引入地面拟合、射线补面或邻格高度复制。
RViz按序抽样的独立显示问题不包含在本次修复中。

## 验证

1. 相同真实输入对照：周围+0.01米平地，中心随后收到三个-0.01米点。
   旧逻辑返回 `unknown_footprint`；修复后自动返回 `ready`。前后原始表面数量和中心真实点数、高度完全一致。
2. 29个建图单元测试通过，其中新增6个用例，覆盖不同切片高度、未成熟到成熟、输入批次顺序、
   继承范围不递推、继承转原生、多楼层真实表面区分以及低净空仍受阻。
3. 原生PCT新增路径验证：后来成熟的地面恢复起终点准入，A*成功生成路线。
4. 核心8项CTest及隔离ROS域7项流程测试验证地图、前沿、层析规划、局部/全局切换、脱困、点云来源与发布。

运行中的Gazebo实例没有重启；新进程启动后加载本次修复。现场截图中灰斑的消除幅度仍需实际跟踪确认。
真实缺少观测、低净空或障碍形成的不可通行区域仍由原有条件判定。
