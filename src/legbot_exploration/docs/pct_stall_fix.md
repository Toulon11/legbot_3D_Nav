# 不可达观察点与长时间候选搜索

## 可达性预筛

`pct_connectivity.py` 保存分块的可通行 XY 索引：每个块只保存本地连通标签，块之间保存边界连接。G、净空、未知、硬膨胀或地形代价变化后，只重算受影响的块。普通目标查询复用块分量图。

这是原生 PCT 图的**宽松必要条件**：合并各切片的可通行 XY 投影，只用“不连通”排除目标。“连通”仍须由原生 A* 判断具体高度、切片及 gateway。投影不用于生成路线，也不改变前沿按高度区分的规则。它允许额外连接，避免误删原生算法可能找到的跨层路径。

观察点会先按机器人分量筛选；缓存观察点都不可达时，从同一簇重新寻找可达观察点。仍无可达观察点的前沿保留为未解决，不当作探索完成。

## 不连通缓存

`BlockPlanner` 保存最多 128 条原生失败结果，键包含起终点格、起终点切片集合及地图范围，依赖包含该次搜索读过的地图块版本。相关块或地图范围变化后重新搜索，无关变化不会清空该失败。投影不连通由增量分量索引直接回答。

**超时不作为不连通缓存。**诊断原因 `pct_planning_timeout` 对应 `failure_class: timeout`；原生搜索没有找到路径才报告 `pct_route_disconnected`。

## 时间预算与公平继续

- `multi_layer_map.yaml / pct_planning_budget_seconds: 1.5`：一次普通端点请求所有切片组合共用的原生搜索预算。脱困请求至少保留 2 秒预算。
- `exploration.yaml / pct_candidate_round_budget: 1.0`：控制器在候选和观察点之间检查的轮次预算。当前一次请求会先结束，因此不是整轮 1 秒的硬实时保证；地图提交、选点查询及显示也另计。
- 超出轮次预算后报告 `pct_planning_yield` 并释放读取阶段。保存候选游标、簇版本及实际观察点列表，下一回合继续后续候选和未尝试观察点。
- 一轮最多尝试四簇，但后续回合从游标继续，不再永远只尝试评分最高的四簇。超时后的短暂重试等待为 2 秒，完整失败沿用既有失败冷却。

搜索时间上限默认关闭于 PCT 原有 API；在线适配器显式开启。未超时的搜索邻接、代价、切片切换和 RDP 输出方式不变，不增加简化后的走廊复查。

## 诊断字段

`pct_unreachable_observers` 为本次预筛掉的缓存观察点数量；`pct_query_ms` 为本次查询耗时；`pct_map.connectivity` 包括本批检查/重标记块数和耗时。`backend.anchor_search` 可区分 `prefilter`、`cached_disconnection` 与 `timed_out`。`search_nodes` 是创建的原生稀疏节点数，不是严格的扩展节点数。
