# exploration 零基础代码阅读指南

这份指南配合当前 C++ 探索器源码中的中文注释阅读。源代码的注释解释语句和参数，本文先解释“为什么要这样做”。旧 Python 探索器存放在项目根目录 `tmp/legacy_python_explorer_2026-10-29/`，不再由启动文件运行。

## 先认识五个词

1. **话题**：ROS 2 节点之间持续传递消息的通道。例如 `/slam/global_odometry_base` 持续提供机器狗机体位姿。
2. **回调函数**：有新消息到达时，ROS 自动调用的函数。例如 `on_cloud` 在收到点云时执行。
3. **体素**：三维空间中的小立方格。默认边长 `0.25 m`。代码里的 `(x, y, z)` 是整数格号，实际位置要乘以分辨率。
4. **二维网格**：把机体高度附近的三维体素压到水平面后得到的方格。这里 `0` 是已观察空闲，`1` 是已观察障碍；字典中没有这个格子，才是未知。
5. **前沿**：与已观察空闲格相邻的未知格。机器人朝前沿移动后，雷达通常能看到新的区域。

## 从输入到机器人运动

```text
/slam/global_cloud_registered ──┐
/slam/odometry_lidar ────────────┼→ 对齐时间戳 → 体素证据地图
/slam/global_odometry_base ──────┘                   ↓
                          机体高度附近的二维占用/空闲网格
                                            ↓
                            未知边界 → 聚类 → 路径搜索 → 评分
                                            ↓
                     /scan/waypoint_input → SCAN → 机器狗运动
                                            ↓
                         SCAN 到达回执 → 继续发送下一路点
```

`/slam/*` 是定位适配器统一对外发布的话题。Gazebo 真值、FAST-LIO2 和 FAST-LIVO2 任选一种，探索包读到的接口相同。已配准点云是点坐标已放到地图系的一帧数据；**长期累计地图由本包的 `VoxelMap` 维护**。

## 地图为什么有“证据值”

雷达从传感器位置出发，到某个点云点结束。代码把射线走过的体素证据减 `1`，把处在障碍高度范围内的终点证据加 `3`；最终夹在 `[-3, 6]`。正数表示障碍，零或负数表示观察为空闲，没有记录表示未知。这样，一条后来的空闲射线不会立即抹掉先前观察到的障碍点。

`integrate` 执行三维证据更新。`project` 只取机体高度附近的格子，再压成二维地图。高度使用“采集该帧时的机体高度”为基准。

## 全局完成是怎样检查的

`assess_coverage` 在配置的单层矩形中逐格查看 `project` 的结果：字典没有该格就是未知，值为 `0` 是已观察空闲，值为 `1` 是已观察障碍。`assess_reachable_coverage` 再从机体位置搜索连通区域：已知障碍按机体半径膨胀后不能通过，未知格仍按潜在通路处理。`reachable_unknown_cells` 为连通范围内尚未观察的格数；其为 `0` 且完成条件持续满足时才能宣布全局完成。障碍内部或被已知障碍隔开的未知格单独记为 `excluded_unknown_cells`。节点把原始网格作为 `/exploration/coverage_grid` 发布；在 RViz 中 `-1` 仍表示未知。

普通前沿暂时没有、但仍有可达未知格时，`select_observation_goal` 还会沿已知空闲格搜索，尝试找到能看见剩余未知格的观测位置。候选点本身必须已知空闲，并避开膨胀障碍；如果没有合适位置，状态是 `unknown_regions_unobservable_or_unreachable`，任务仍然未完成。地图已满、数据过期、边界无效、无法确定连通起点或还有活动目标，也不能通过完成检查。

`truth_coverage.py` 是独立测试工具：读取 Gazebo 的平面场景，计算从出生点能够走到的地面格，再与探索发布的网格比较。它不把场景几何交给探索算法。

## 如何选一个探索点

`select_frontier` 依次做六件事：

1. 把已知障碍按机器人半径向外扩张，得到不能选作目标、也不能穿过的格子。
2. 找出与已知空闲格四邻接的未知格，这些是原始前沿格。
3. 用八邻接把相连前沿格聚成簇；小于 `min_frontier_cells` 的簇先不参加普通选点。
4. 从机器人当前格运行一次 Dijkstra 最短路。允许经过未知格，但乘 `unknown_path_multiplier`，表示它比已知空闲格更贵。
5. 每个簇选择靠近簇中心的**实际格子**。过远时，沿搜索到的路径找一个距离合适的已观察空闲格作为分段目标。
6. 过滤距离过近、近期失败或被 SCAN 判为障碍的目标，按“前沿簇规模收益减路径成本”选择最高分。

代码里 `frontier_cells` 是原始前沿格数，`clusters` 是通过规模门槛的簇数，`candidate_goals` 是通过距离筛选的候选数。这几个数不相等是正常的；`/exploration/status` 会输出它们，便于分析为什么未发新目标。

## 为什么机器人会暂时不动

C++ 的 `Explorer::tick` 每秒执行一次状态机。它先检查点云和里程计是否新鲜、上次目标是否仍在执行、GO2 是否就绪，再决定发新目标。常见状态如下：

| 状态 | 含义 |
| --- | --- |
| `waiting_for_fresh_data` | 点云或机体位姿过期，先等新数据 |
| `waiting_for_free_space` | 地图尚未形成可用于搜索的空闲格 |
| `waiting_for_planner_occupancy` | 当前配置要求 SCAN 障碍图，正在等它更新 |
| `waiting_for_coverage_confirmation` | 可达未知格已清零，正在等待持续复核时间 |
| `goal_sent` | 已发送一个探索目标 |
| `waiting_for_scan_forward` | 已发布路点，等待 SCAN 转发目标 |
| `waiting_for_scan_completion` | SCAN 已转发目标，等待停车回执与任务完成信号 |
| `frontiers_unreachable_or_suppressed` | 有前沿，但路径不可达或目标正在冷却 |
| `current_region_complete` | 局部窗口持续没有前沿；只代表当前区域 |
| `exploration_complete` | 全图边界内从机体可连通的未知格为零，且连续复核通过 |
| `waiting_for_reachability_seed` | 起点附近没有可靠的已观察空闲格，暂不判断完成 |
| `unknown_regions_unobservable_or_unreachable` | 无普通前沿，但边界内仍有未知格，当前找不到补充观测点 |
| `observation_only` | 仅计算并显示目标，不让机器狗运动 |

若 SCAN 确认到达目标后没有新增足够多的已观察格，`GoalProgressGate` 暂时屏蔽该目标；`RecoveryPlanner` 按物理区域累计选点和规划失败次数。脱困按附近短目标、分步转向、历史回退的顺序尝试。路点执行期间，探索器只等待 SCAN 完成回执，不按超时或地图变化撤销目标。

## 看代码时的语法提示

- C++ 的 `xxx_` 通常表示对象内部保存的状态；`std::optional` 的空值表示“暂时没有”。
- `std::unordered_map` 是“键 → 值”的表；本包用它只保存观察过的体素，未存储的体素保持未知。
- `std::queue` 可用于先进先出搜索；`std::priority_queue` 用于优先处理最小路径代价。
- `return` 结束函数并把结果交给调用处；`continue` 跳过本轮循环；`break` 退出当前循环。
- `if` 后面花括号内的代码只有条件成立才执行。跨多行的表达式是一条逻辑语句，所以源码通常在整个表达式前解释，不给每一行括号重复写注释。

## 最小阅读练习

在项目根目录运行：

```bash
colcon build --base-paths src/legbot_exploration --cmake-args -DBUILD_TESTING=ON
ctest --test-dir build/legbot_exploration --output-on-failure
```

然后先在纸上推想，不改源码：`resolution` 变小、`min_frontier_cells` 变大、`unknown_path_multiplier` 变大，各会影响哪一步。最后对照 `test/test_single_floor_exploration.cpp` 的输入点、预期前沿和断言验证自己的理解。
